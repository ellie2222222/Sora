# Test plan: Dashboard & exchange rates

**Stories:** SRS §9 DASH-US-01 Wallet dashboard · DASH-US-02 Compare wallets · DASH-US-03 Approximate total in one currency · DASH-US-04 Account dashboard
**Contract:** API spec §14 Dashboard; SRS BR-16 and SDS §4.5 (exchange rates); `plans/architecture/exchange-rate-resilience-plan.md`
**Rules:** BR-06 (transfers are neither income nor expense, reported as `transferredIn`/`transferredOut`), BR-07 (per currency, never summed; the converted total is read-only, approximate and freshness-marked), BR-05, AC-01
**Code under test:** `server/src/dashboard/`, `server/src/exchange-rate/`, `packages/contracts/src/calc.ts` (`countsAsPeriodActivity`, `transferDirection`), `mobile/src/features/dashboard/`, `mobile/src/utils/dashboardPeriod.ts`, `mobile/src/utils/dashboardAnalytics.ts`, `mobile/src/services/guest/guestDashboard.ts`

## Objectives

1. Income, expense and net exclude every transfer, at wallet and at account grain.
2. No figure ever adds two currencies, except the optional converted total, which is always marked approximate and never breaks the dashboard.
3. Period boundaries are calendar days and calendar periods, with no gaps or overlaps between consecutive windows.

## Test data & environment

- Fixed period `2026-05-01..2026-05-31` and an instant before it ([integration.ledger:19](../../server/test/integration.ledger.test.ts#L19)). Each dashboard test registers its own user, so its figures are exact.
- Exchange rates: `globalThis.fetch` is stubbed per test. `setup.ts` makes an unstubbed `fetch` throw ([setup.ts](../../server/test/setup.ts)). The persistence suite boots a fresh app per step, so the in-memory cache doesn't hide the snapshot path.
