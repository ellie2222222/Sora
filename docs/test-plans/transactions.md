# Test plan: Transactions

**Stories:** SRS §9 TXN-US-01 Income · 02 Expense · 03 Same-wallet transfer · 04 Cross-wallet transfer · 05 Browse & filter · 06 Detail · 07 Correct · 08 Cancel (delete)
**Contract:** API spec §11 Transactions, §2.8 Pagination/sorting, §2.10 Idempotency, §16.3 Deletion policy
**Rules:** BR-02 (cross-wallet transfer needs EDITOR on **both** wallets), BR-03 (every field editable in place, checked as a create), BR-06 (a transfer is neither income nor expense), BR-07 (currency matches every account named), VL-04, AC-01, AC-03, LA-02 (a cross-wallet transfer is audited once per wallet), API-05/06
**Code under test:** `server/src/transactions/`, `packages/contracts/src/schemas.ts` (`createTransactionSchema`, `updateTransactionSchema`, `transactionQuerySchema`), `packages/contracts/src/calc.ts`, `mobile/src/features/transactions/`, `mobile/src/utils/transactionForm.ts`, `mobile/src/utils/calculatorEngine.ts`

"Cancel" is the user-facing word for this action; the stored status is `DELETED` and the error is `TRANSACTION_ALREADY_DELETED`. SRS TXN-US-07/08 and the API spec agree.

## Objectives

1. A refused write leaves no row behind and moves no money.
2. A cross-wallet transfer is one row: it moves both balances, appears in both wallets and both audit trails, and is income or expense in neither.
3. A recorded movement can't be rewritten; correcting one is delete + create, and both rows stay.
4. The form, keypad and sheet on the device produce exactly the request the server expects.

## Test data & environment

- `integration.ledger.test.ts` creates one owner with two wallets and fixed accounts in `before()`. Tests that need exact figures create their own user or account (`ledger-dash`, `ledger-acct-dash`), so shared balances can't leak between them.
- Fixed instants `IN_PERIOD = 2026-05-10T09:00Z` and `BEFORE_PERIOD = 2026-04-20T09:00Z` ([integration.ledger:19](../../server/test/integration.ledger.test.ts#L19)).
- E2E descriptions are unique per run (`'E2E sheet expense ' + Date.now()`), and every write is read back through the API ([scripts/find-transaction.js](../../mobile/e2e/scripts/find-transaction.js)).

## Gaps, by risk

None open. TC-TXN-09 found `TRANSFER_CURRENCY_MISMATCH` unreachable: the per-account check ran first. The server and the guest copy now check the transfer pair first. A same-account transfer is refused by the shared schema, so §11.2 and the SRS now name `VALIDATION_FAILED` for it.
