# Test plan: Budgets

**Stories:** SRS §9 BUD-US-01 Create · BUD-US-02 Watch · BUD-US-03 Adjust · BUD-US-04 Archive
**Contract:** API spec §12 Budgets
**Rules:** BR-04 (no overlapping ACTIVE budget per category, GIST exclusion), BR-05 (`spent`/`remaining`/`usage` derived on read), BR-06 (transfers never count), BR-07 (only the budget's own currency counts), rule 5 (overlap can't be a unique index)
**Code under test:** `server/src/budgets/`, `server/src/common/pg-error.ts`, `packages/contracts/src/calc.ts` (`calculateBudgetSpent`, `calculateBudgetRemaining`, `calculateBudgetUsage`, `isWithinPeriod`), `mobile/src/features/budgets/`, `mobile/src/services/guest/guestBudgets.ts`

> **Budget kinds (migrations 008–011, specified 2026-10-02).** A budget targets one category, one goal (period GOAL), or the whole wallet; SRS BUD-US-01/02 and API spec §12.2 define what each counts. `chk_budget_kind` (011) holds the shape for any writer. Expenses reach a goal budget through their `goalId` tag, which a recorded contribution's expense carries too.

## Objectives

1. Two active budgets for one category never cover the same day; an archived one never blocks.
2. `spent` counts exactly the completed expenses of that category, in that currency, by calendar day within the window. Transfers, pending and deleted rows never count.
3. Overspending is visible: remaining goes negative and usage goes above 100%.

## Test data & environment

- `integration.planning.test.ts` uses one user and a fixed window around `IN_WINDOW` ([integration.planning:11](../../server/test/integration.planning.test.ts#L11)). Overlap tests use a second category so they don't collide with the spend tests.
- `calc.test.ts` uses the SQL suite's fixture ledger: an August food budget with 1,150,000 spent ([calc:217](../../packages/contracts/test/calc.test.ts#L217)).
